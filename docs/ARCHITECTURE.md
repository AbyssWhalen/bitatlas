# 架构与运行模式

## 2026-11-20 服务器版

新增 `apps/server`，Node24/Fastify5/SQLite WAL 提供同源 `/api/v1` 与前端应用壳。共享文件在私有目录，按内容摘要寻址；题包与文件均鉴权，静态产物不复制 `public/content`。成员之间学习数据隔离，管理员独立发布内容。

服务器模式使用 `408-user:<accountId>` v5、`408-content:<accountId>` v3，原匿名 `408-user` 保持v4作为显式迁移来源。仓储写入与outbox在同一事务，服务端按账号/operationId幂等提交，epoch游标支持恢复后对账。笔记、个人卡和轮次冲突保留双方，卡片评分重放及原始作答关联由服务端验证。派生进度由原始事件重建。

登录会话由服务器撤销，浏览器离线资格7天。跨账号合计可替换缓存250MB，固定PDF和唯一/未同步记录独立保护；PDF按需Range读取，主动下载才离线保存。学习备份v5包含同步队列与恢复档案，服务端用SQLite一致快照+对象摘要+age归档。详见 [迁移合同](server/migration-v5.md)和[运行手册](server/deployment.md)。

下文的本地/无题包模式保留兼容；其匿名数据和路径不被服务器模式自动归属或删除。

## 分层

```text
apps/web
  React 页面、路由、PWA、浏览器存储装配
        |
packages/domain
  题目、作答、复习、统计和内容复核领域逻辑
        |
packages/content-schema   packages/storage
  内容包校验与迁移        IndexedDB、Cache Storage、备份事务
        |
packages/cpu-core         packages/lab-core
  组成原理实验纯逻辑      数据结构、OS、网络实验纯逻辑
```

页面通过 repository/service 接口访问内容与学习数据，不直接操作 IndexedDB 表。实验计算放在纯逻辑 package 中，页面负责参数输入、状态展示和深链。

## 两种运行模式

### 无题包模式

仓库已包含题包；无题包是可选部署和测试场景。没有已安装 2009 内容且 `/content/2009.json` 返回 HTTP 404 时，`StudyProvider` 保持可启动：

1. 应用壳显示“本地题包未安装”提示。
2. 依赖未安装题包的入口进入禁用或空状态；如果其他年份已安装，仍可浏览和练习对应年份。
3. 四科实验室、本地 PDF、设置和本地数据能力继续可用。

只有预期的本地题包缺失会降级。网络拒绝、无效 JSON、内容校验失败和存储异常继续 fail closed，避免把真实故障伪装成“未安装”。

### 本地题包模式

本机存在 `apps/web/public/content/2009.json` 与对应来源资产时，启动流程校验并安装内容包，首屏就绪后后台加载 2010–2025 可选年份。已安装 verified 题包不会被 `needs-review` 草稿覆盖：最终保护与替换写入同一个内容库事务，覆盖后台下载期间的手动导入和跨标签页交错。题包生成和发布流程见 [LOCAL_CONTENT.md](LOCAL_CONTENT.md)。

扩展年份最多同时下载 2 个文档，并及时读取响应体，为路由模块和其他页面保留连接；随后按年份逐包解析、校验并写入数据库。同 hash 快路径也重新校验 schema 和实际摘要，然后才能写可信缓存。每次启动排入缺失图片检查，逐张校验、逐张提交，前一次中断不会撤销已成功下载的图片；数据页提供状态和手动补齐入口。

## 应用更新与日期

PWA 使用等待式更新。新 worker 下载完成后保持 waiting，所有旧页面退出后才激活并清理旧预缓存；首次安装仍通过 `clientsClaim` 接管页面以支持离线刷新。应用显示新版就绪提示，不发送 `SKIP_WAITING`，不在其他标签页尚有草稿时强制刷新。路由加载失败提供显式重新载入入口。

每日计划以北京时间日期为主键持久保存，午夜、页面恢复可见和窗口恢复时校正日期；今天已分配的任务不随补装、刷新或新成绩改变。计划保存算法版本和当时额度，额度修改次日生效。客观首答统计要求完整过程证据、未提示、未揭示答案；主观自评和卡片自评分开呈现，旧过程证据保持未知。前台计时排除失焦、隐藏及超过 2.5 秒的休眠采样空档，不用于直接推断掌握度。

## 持久化边界

- `408-content` v2：原题包、题目、知识点和资产元数据，以及独立 `LearningPack`。
- `408-user` v4：原学习数据、每日计划、复习轮次、评分事件、个人卡、练习过程证据、重练关系和冲突笔记原文。
- Cache Storage：本地 PDF 字节、经验证的内容文档与来源资产。

这些名称是历史兼容标识。此次 v2/v4 升级已获维护者授权；恢复快照、升级事务、连接阻塞和备份合同见 [migration-v4.md](learning/migration-v4.md)。

## 独立学习内容和复习

`LearningPack` 自有版本和 SHA-256，含概念、799 条显式映射、80 张卡与来源审核信息。`content/learning/` 是编辑源，`learning:build` 生成发布 JSON，`learning:check` 验证确定性。映射逐题绑定 `questionContentVersion`，概念调整不改变题面版本或学习进度。

卡片定义与用户评分事件分离，轮次冻结当时正文。个人修改存为独立副本，公共包安装不覆盖个人内容；暂停与恢复保持内容版本，编辑正文产生新版本。卡片同日同版本取最低自评分；题目同日取最低有效质量，提示后答对最高按 0.5 调度。首次成功间隔 1 天、再次 3 天，随后按难度延长；不足 0.6 则次日再练。轮内失败最多额外重试两次，完成轮次不等于掌握。

仓储负责写事务、版本冲突和幂等。模考 exam/session 联合只读事务避免混合修订；备份一次读事务覆盖所有用户表。普通笔记按题号比较草稿起点版本，冲突时保留页面输入；历史重复项在升级事务中归档全部原文后才合并当前表。

## 内容可信度

内容状态与来源核对、自动测试、人工审核分离：

- `needs-review` 表示尚未完成逐题人工审核。
- schema、hash、资产和来源页校验只能证明结构与输入一致。
- 只有 47/47 ledger 通过独立发布工具后，才能生成 verified 题包。

Q44 的模型固定为 `parallel-5 / split-6`，不扩大为微操作搜索或评分系统。
