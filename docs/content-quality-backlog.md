## PWA / 部署层（2026-09-03 巡检发现）

### 已修复 · SW 不接管已打开页面（commit 3e75f42）

线上实测：SW 激活后（即使经过在线 reload）`navigator.serviceWorker.controller` 恒为 null，
离线 reload 直接走网络失败（直连 3/3）。根因：generateSW 产物只有 `skipWaiting()` 没有
`clientsClaim()`。已在 vite.config.ts workbox 配置加 `clientsClaim: true`。

### P2 · sw.js 被 Cloudflare 边缘缓存

`/sw.js` 走 CF 边缘缓存（origin `Cache-Control: max-age=600`），部署后最长 10 分钟内
新访客仍拿旧 SW（实测带 query 绕过缓存可得新版，无 query 得旧版）。影响有限（skipWaiting +
prompt 更新流），但每次部署后 PWA 行为更新有 ≤10min 延迟。可选优化：CF Dashboard 加
Cache Rule 对 `/sw.js` 设 Bypass cache（需维护者操作，程序侧无法改 CF 配置）。

### P2 · precache 安装在慢网络下分钟级

88 项预缓存（约 2.7MB）在 SW install 时逐项拉取（`cache: 'reload'` 绕过 HTTP 缓存），
国内直连下实测需分钟级。期间离线不可用（SW 未 activated 或 precache 不完整）。
可选优化：`maximumFileSizeToCacheInBytes` 与 globPatterns 收敛（如 KaTeX 字体改 runtime
CacheFirst），缩短首装时间。

### 巡检结论（2026-09-03，国内直连）

- `https://408.fytjut.com/` 连续 5 次 probe 全部 200，TTFB ≈ 0.9-1.1s，直连稳定。
- 题包 JSON：CF `cf-cache-status: DYNAMIC`（不边缘缓存，回源 github.io），浏览器侧
  max-age=600 但应用以 no-store 自取；每次启动拉全量 JSON（≈2.8MB）属既有设计
  （更新检测 + sha256 校验），重复启动命中「未变化跳过重写」，不再重装 IndexedDB。
- 来源页 JPG：CF 边缘 HIT（max-age=14400），第二次起回源流量为零。

## 扫描方法

关键正则（`output/quality-scan.mjs`，本地未提交）：
- 图示引用：`/(下|上|如|右|左|该)图|图所示|图中|如图|示意图|流程图|题\s*\d+\s*图/`，配「题干无 image 块」判定；
- 解析占位：explanation 含 `暂缺` 或 `见来源页`；
- 形近错字：`大千/小千/等千/由千/对千/关千/位千/处千/千是/大干/.../己知/己经/己满/己分配/己排/己注/己完成` 白名单；
- 上标丢失：`/O\([a-z]+[0-9]\)|[a-z]1\/2\)|\^2|\^n|n\^|[0-9]\/2\)/`。

内容变更必须走 `tools/content-importer/src/build-year.mjs` 重建（`content:validate` 强制
published == generated），不得直接手改 `apps/web/public/content/*.json`。
