# 本地学习数据升级与恢复

适用于 2026-11-20 的本地升级。公开部署须另行授权。本次只升级既有数据库内容，不重命名 `408-user`、`408-content` 或缓存标识。

## 版本与存储

| 内容 | 升级后 | 合同 |
| --- | --- | --- |
| 题目内容库 | `408-content` v2 | 保留题目、资产和题包，新增独立学习包 |
| 个人学习库 | `408-user` v4 | 保留 v1–v3 记录，新增计划、卡片、评分、过程证据及冲突原文 |
| 学习备份 | schema v4 | 导入合法 v1/v2/v3/v4；旧应用不能读取 v4 |
| 恢复快照 | `bitatlas-recovery-v1` | 原始表、旧库版本、创建时间及 SHA-256，不丢弃重复笔记 |
| 本地 PDF | 原 Cache Storage | 独立保存，不进入学习备份 |

新增领域接口分为学习内容仓储与复习仓储。练习过程证据、重练来源放在旁表，原 Attempt 和 session 记录继续保留；旧记录的提示、首次作答和前台时间不补造为已知证据。题目进度仍绑定原题 ID 与 `contentVersion`，重新分类不会清空进度。

## 首次打开新版

1. 入口先动态只读检查旧库，尚未挂载学习 Provider，也不提前定义高版本打开数据库。
2. 存在旧数据时，先下载升级前恢复快照。旧数据能合法表示为原版备份时，同时下载旧版备份；重复笔记导致旧格式无法表达时，明确保留完整恢复快照。
3. 保存其他 BitAtlas 页面输入并关闭旧页面，勾选页面说明后开始兼容升级。下载操作是浏览器文件保存入口，仍应确认文件实际保存在自己的下载目录。
4. 升级前再次读取并比较原始表；若有并发修改，重新生成快照并要求重新下载。
5. Dexie 版本升级事务内部再次保存原始表快照，再执行增量迁移。任何步骤抛错会回滚整个升级，旧库仍可重新检查并重试。

升级被旧连接阻塞时，当前页面显示等待原因；旧连接关闭后自动继续，不用清空浏览器数据。新版连接收到 `versionchange` 会停止写入并关闭，页面提示先复制未保存输入再重载。隔离浏览器测试覆盖不配合关闭的旧标签页、连接释放、未保存输入和真实 v3→v4。

## 重复笔记与冲突

历史同题多条笔记在同一个升级事务中完整写入 `noteConflicts.originals`。当前笔记表确定一条记录，其他条目从当前表移出，但全文仍在恢复快照和冲突档案中。数据管理页可逐份展开原文并编辑合并结果；保存合并后原文档案仍保留。

新笔记按题号在事务内保存，首次并发创建只允许一个成功；过期版本写入或删除拒绝并显示冲突。本地草稿按开始编辑时的版本比较，不用后台刷新到的新版本悄悄覆盖另一页内容。

## 备份包含与不包含

包含作答、版本化与 legacy 进度、练习会话、笔记、冲突原文、收藏、设置、人工复核记录、模考、每日计划、复习轮次、卡片事件、个人卡片、错因和练习证据。导出从一个只读事务取得一致快照。

不包含本地 PDF 字节、题包、学习内容公共包或来源图片缓存。PDF 请保留原文件；题包和公共学习包可重新安装。个人卡片属于用户数据，包含在 v4 备份内。

导入先解析、schema 校验、交叉引用和事件重放校验；损坏摘要、悬空事件、错误版本、矛盾会话、非确定性事件 ID 与无效额度均拒绝。替换在一个事务中清理并写入用户表，失败完整回滚。底层合并仅接受无歧义并集，不猜测同 ID 的覆盖胜者。

## 恢复与限制

- 在数据管理中导入升级前快照，可恢复快照时点的记录；不会包含升级后新增学习。恢复前先导出当前 v4 备份。
- 合法原版 v1–v3 备份可继续导入；无法证明题面版本的旧记录保持 legacy，不自动投影到当前题面。
- 旧应用不支持读取 v4 数据或 v4 备份。回退旧应用时，使用在旧版本环境创建的独立浏览器资料及升级前合法旧备份，不能直接让旧应用覆盖 v4 数据库。
- 摘要验证完整性，不提供加密或身份认证；备份应作为个人资料保存。
- 迁移恢复验证使用隔离浏览器和 fake-indexeddb，未读取或迁移用户真实浏览器资料。真实硬件断电不可由事务注入失败等同证明。

关键验证：`packages/storage/src/learning-repository.test.ts`、`backup-v2.test.ts`、`backup-v3.test.ts`，以及 `tests/e2e/learning-loop.spec.ts`。本轮结果和失败记录见 [验收报告](acceptance-2026-11-20.md)。
