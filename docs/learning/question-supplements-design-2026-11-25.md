# 题目补充解析与勘误设计

2026-11-25 · 设计待维护者裁定 · 基于 `main` 的 `b69115c`

建议在独立学习包中增加 `questionSupplements`。成员查看答案时，应用按题目 ID 和题面版本取出对应条目，放在原解析或原卷缺解析提示旁。2024、2025 年各 40 道单选题可分批补充，2023 Q40 可先单独勘误。三套题包都可以逐字节保留，已有作答继续计入当前版本。[内容质量清单](../content-quality-backlog.md)

**需要维护者先决定的是学习包内容格式升级，以及 Q40 勘误的发布。** 现行 `learningPackSchema` 要求 `schemaVersion: 1`，顶层使用 `.strict()`。给 v1 加一个可选数组只保证新程序读旧包；已安装的旧程序读到该字段会拒绝整个包，156 张卡也受影响。建议把带新字段的包明确标为 **学习包 JSON v2**，保留 v1 读法。下表中的版本彼此独立。[现行学习包校验](../../packages/content-schema/src/learning.ts) · [当前生产基线](card-release-2026-11-25.md)

## 条目与证据

在 `packages/domain/src/learning.ts` 定义 `QuestionSupplement` 和学习包 v1/v2 联合类型。v1 按原字节语义验证，读取时视为零条；v2 保留原包各字段，要求顶层 `questionSupplements: QuestionSupplement[]`，允许空数组。以下为每条的作者合同。

| 字段 | 约束 |
| --- | --- |
| `id`、`version` | 稳定 ID 与独立的数字点分版本。单题单版本首期最多一条，可在正文中说明多处关联错误。包内 ID 及 `(questionId, questionContentVersion)` 各自唯一。 |
| `questionId`、`questionContentVersion` | 作者显式锁定两值。包内须有精确匹配的 mapping；读取时再与当前加载的题对象匹配。禁用仅按题号、年份或“最新版本”匹配。换版后由作者重新核对并显式绑定，生成器不得自动贴到新题面。 |
| `kind`、`body` | `supplement` 解释原卷缺文的题；`erratum` 给出更正和推导。`body` 为 1–100 个有实质内容的既有 `ContentBlock`，首期限定文字、数学、代码、表格。可离线完整阅读。 |
| `sectionId`、`originalExcerpt` | 仅 `erratum` 必填，分别指向原解析段及其中一段短的原样文字。校验引文属于该段。公式上标转录失真时可选一段未失真的文字，原页仍由来源定位。 |
| `sources` | 至少一条。沿用 `LearningSource` 的题 ID、题版、PDF SHA-256、页码、locator，并明确 `role: 'question' 或 'answer'`。本期两种条目都须有答案卷来源；补充解析另附题卷来源。页码沿用来源记录的精度和疑点。 |
| `authorship`、`reviewStatus` | 首批固定为 `ai-assisted`、`needs-review`。来源只证明所引题面、答案表或原页；推导属于作者。审核字段由生成器显式写入，解析器拒绝擅标已审核的条目。 |

**Q40 的实际绑定。** `cn408-2023-q40`、`2023.0-draft.2`、`q40-analysis`，引文可用“二者相差了 64 位”。答案卷定位为 `PDF page 11; answer 40`，原页也有这处错误。勘误正文可写“IPv6 与 IPv4 的地址长度相差 128 − 32 = 96 位。完整地址空间大小之比为 2¹²⁸ / 2³² = 2⁹⁶。”这是理论地址空间之比。答案键 D、原文字和原图均保留，`card-cn-31` 也无需改动。2024 和 2025 的目标分别绑定 `2024.0-draft.2`、`2025.0-draft.2`；答案表定位若写有 `page 1 assumed`，界面应照实标明。[Q40 来源核对](../content-quality-backlog.md#p2--2023-q40-ipv6-地址空间倍率解析错误2026-11-25)

**校验分两层。** 在 `packages/content-schema/src/learning.ts` 增加严格的两种条目分支，验证字段、正文、重复键、mapping、来源绑定和整包摘要。v1 验摘要前不可补空数组。增加一个接收实际题对象的共享校验，供生成器和服务端 preview 复用：按 `role` 分别与 `question.source.question` / `question.source.answer` 比对文档摘要、页码、locator；补充要求 `questionAvailability(question).explanationMissing`，勘误要求目标段与短引文匹配。现有 `mapping.source` 取的是**题卷**，直接复制它会把 Q40 错引到题页。条目不会消除原卷的 `missing-explanation` 事实。[来源生成逻辑](../../tools/content-importer/src/build-learning.mjs) · [缺解析判定](../../packages/domain/src/availability.ts)

## 生成、发布与旧客户端

1. 扩展 `tools/content-importer/src/build-learning.mjs` 的候选生成和确定性检查，以同一份已核对的学习包为基线，按稳定键排序条目，固定发布时间，用 `computeLearningPackHash` 计算整个规范对象的摘要。新增或修改条目时提升整包业务版本；改正文、引文、来源或审核信息还须提升该条版本。生成和 preview 都应核对前次版本，拒绝同一条目同版换文。旧概念、映射、卡、讲解逐对象比对。下一版以发布时实读生产值为准；`2026.11.25.1` 是本设计基线，`.2` 已被上一轮 80 卡回退包使用。
2. 题源和答案页按现有发布范围处理。候选生成增加显式的服务器输出目录，受邀成员版的正文、输入和核验材料留在已忽略的本机目录，经管理员接口上传。现有生成器默认把 `learning.json` 写入可跟踪的 `apps/web/public/content/`；不能用这条默认输出路径发布尚未获准公开的逐题材料。静态本地模式继续读取获准的 v1 学习包，合成测试可喂入 v2；私有候选不进入 Pages、静态缓存预置或应用部署包。[构建入口](../../apps/web/vite.config.ts)
3. 在 `apps/server/src/content.ts` 的 `ContentService.preview` 学习包分支复用新校验，与**当前已发布**题包比对，返回两类条目计数、缺题、版本错配、来源或引文错误以及 blockers。对扩展包，preview 还返回当前学习包的完整摘要；发布工具先与制作候选时的基线比对，再将其作为 `expectedCurrentDigest` 连同候选的 `expectedDigest` 传给 publish。写事务内复核基线及依赖，若其间已发布新讲解，返回冲突并基于新包重做候选。继续拒绝同版异摘要及降版。沿用管理员 POST 与成员鉴权 GET。以后发布新题包时，旧条目即使尚在当前学习包，客户端也按题面双键失效；下一次学习包候选须删去或重新核对此条。
4. 已安装旧 PWA 仍可能打开。建议两种 GET 表示共用同一条已发布记录：现有 `/api/v1/content` 及 `/api/v1/content/bitatlas-learning` 默认返回严格 v1 表示，新读端在**目录和正文**都加 `?learningFormat=2`。v2 的 v1 表示由剔除补充数组、设 `schemaVersion: 1`、重算摘要得到，保留同一业务版本和时间。原包是 v1 时两种读法都原样返回。每个目录给出其正文的真实摘要；管理员 preview、publish、发布回读使用完整候选摘要。表示按已发布摘要复用，避免每次请求都重算。题包条目不参与转换。旧标签页可以继续学习，新标签页才显示补充；一次内容更新可能使旧端重取一次学习包。[现有 GET 和事务](../../apps/server/src/content.ts) · [PWA 更新行为](../../apps/web/src/app/pwa.ts)

## 成员影响、验收与回退

只用补充内容渲染答案区。旧作答、错题统计和掌握度仍按原 `questionContentVersion` 汇总；首答／揭晓证据、个人笔记、模考计分和蓝图均保留原记录。排序、每日清单、卡片事件和重放日程沿用原输入；补充没有卡 ID，不参与选题或排卡。服务器正常生成新日清单的调用也无需改规则。[学习上下文](../../apps/web/src/app/LearningProvider.tsx) · [前次学习包发布与回退](card-release-2026-11-25.md)

| 实施时的验收 | 通过条件 |
| --- | --- |
| 格式、发布与内容差异 | 原 v1 摘要验证通过，两种表示各自目录与正文一致；重复键、错版、假页码、错引文、同版改文、擅标审核、预检后题包变化均阻断。单条试点只命中 Q40；最终为两年各 40 条补充、1 条勘误。17 套题包摘要以及原学习对象逐项比对。 |
| 浏览器与成员状态 | 桌面／手机验证练习揭晓前后、模考提交前／提交失败／交卷后、错题展开与重练；比较已有作答计数、当日固定清单、卡复习日程及 outbox。覆盖无学习包、换题版、双标签新旧程序、暖缓存离线、切换账号、损坏摘要及缓存安装失败。 |
| 回退演练 | 在本地用正式 preview → publish 流程发布较高版本的回退候选并回读两个目录／正文，再验证两代客户端与离线恢复。线上只用管理员发布、只读验收，匿名内容接口仍返回 401。 |

**撤回一条**时从当前学习包仅移除该条，保留期间新加的卡、讲解和其他补充，提升整包业务版本。**撤回整个功能**时先核对线上摘要，把当时应保留的全部基础学习对象制成更高业务版本的 v1 包，预检、发布并回读；再视需要回退应用。不得复用今天留作旧 80 卡回退的 `.2`，也不可直接降版。移除条目的回退本身无需恢复 SQLite 快照或清除用户缓存；离线端按正常更新时机收敛。后续恢复同一条目时沿用 ID，并以新条目版本发布。

## 工作量与实施顺序

| 顺序 | 预计投入（一人） | 交付 |
| --- | --- | --- |
| 1. 合同与候选 | 0.5–1 人日 | 维护者确认学习包 v2 与 Q40 试点；双读 schema、来源对照、私有候选生成、v1 摘要回归。 |
| 2. 发布和离线兼容 | 1–2 人日 | 双表示目录与正文、preview/publish、缓存事务；严格旧端与新版同账号并存、跨账号、回退夹具。 |
| 3. 三处阅读入口 | 0.5–1 人日 | 共享组件、揭晓时机、错题展开、交卷后查看，手机和桌面定向验收。 |
| 4. 分批发布 | 0.5–1 人日工程验收 | 先部署能读两种格式的应用并以旧包验收，再发 Q40；随后从两年各挑一题，验证来源和推导，再按已核对清单分批补齐。每批先预检、保留高版本回退候选，记录题包摘要、条数与成员只读验收。 |

工程约 **2.5–5 人日**。80 条正文按每条 20–40 分钟撰写和核对估算，另约 **27–54 小时**；涉及图题与表格时先抽样校准。内容人工复核排期单列，发布不会自动获得“已审核”状态。仅修 Q40 的低成本过渡办法是提供一份受邀成员可读的勘误说明并引用已有 `card-cn-31`，约 0.5–1 小时整理，无格式变化，成员需要离开题页查找。若目标是让 81 道题都能在原解析处准确、离线可查地补正，建议实施学习包方案。把补充另设为第三种服务器内容 `kind` 会碰到 SQLite 的 `CHECK(kind IN ('questions','learning'))`，需要另行批准数据库变更，不能按“简单加接口”估算。[服务器表定义](../../apps/server/src/database.ts)
