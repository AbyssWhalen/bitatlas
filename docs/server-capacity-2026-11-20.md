# BitAtlas 境外服务器容量与费用评估

核验日期：2026-11-20，北京时间。范围：用户授权的探针面板只读查看、项目已有构建清单核算、官方价格与限制核验。未部署、修改 DNS/网络档位、登录云账单或开通收费服务。

需求后续澄清：初期本人使用、最终十几位受邀用户，按一台 GCP 运行完整应用设计，北京腾讯云不是必要组件。电脑用于开发，非开发常驻文件希望不超过约 1 GB；完整备份改为独立远端保存，目的地待选。具体下一阶段建议及最新本机扫描见 [自托管方案](server-first-plan-2026-11-20.md)；服务器容量测量仍沿用下列原始时点，未执行新负载测试。

## 判断

- **当前静态学习站适合现有 GCP，信心高。** 已有生产构建清单仅 85.39 MiB；探针显示该节点约 25.27 GB 磁盘未用。运行内存不是资料存储容量上限。
- **增加轻量账号与学习记录同步，按十几人邀请使用设计，信心中。** 用户后续明确规模，原 5–10 人初步估计更新为约 10–19 人设计、20 个模拟活跃用户验收目标。单进程 API、同机 SQLite、按需资料分发是候选；尚未实现服务端或压测，不能宣称已验证并发承载人数。SQLite 官方将低中流量网站列为适用场景，但写入仍需排队，实际表现取决于事务与查询。[7]
- **先核对网络档位，再决定是否花赠金买流量。** GCP Premium 与 Standard 的费用规则不同；Standard 官方价目表列每账号跨区域合计每月前 200 GiB 免费，不能将 Compute Engine 免费层的 1 GB 概括为所有网络档位的唯一额度。[1][2]
- 建议保留现有域名，按一台 GCP 承担前端文件、轻量 API、数据库和初期资料的完整方案设计；现有静态托管可在迁移验证期继续使用，独立对象存储属于后续可选优化。尚未实施部署。日本节点即将到期属于用户提供的信息，不作为长期主节点。北京节点仅可作为独立远端备份或未来批处理候选，不作为初期应用依赖。

## GCP 费用规则与情景

以下为官方公开美元价格参考，不是该账户的报价或账单。

### 两种网络档位

| 路径 | 当前官方规则 | 对本项目的意义 |
| --- | --- | --- |
| Compute Engine 免费层 | 指定美国区域的 `小型通用机型` 时长、30 GB-month 标准持久盘；北美出站 1 GB/月不含中国和澳大利亚 | 需核对区域和磁盘类型，不能只凭“免费实例”判断整机费用为零 [1] |
| Premium，美国到中国大陆直连 | 首 1024 GiB 档 $0.23/GiB | 10/30/50 GiB 纯出站约 $2.30/$6.90/$11.50；尚未加 IP、其他服务和税费 [2] |
| Standard | 价目表列每账号、所有区域合计前 200 GiB/月免费；美国随后至 10 TiB 档 $0.085/GiB | 当前实例是否使用此档未知；应核对资源档位、账单 SKU 与其他服务共享的使用量 [2] |
| 普通常驻 VM 使用中的公网 IPv4 | $0.005/小时 | 按约 730 小时估算约 $3.65/月；是否已有抵扣应看账单 [2] |

本次采用价格页明确的“每账号、跨区域合计”口径，不据此规划多区域叠加额度。[2]

Standard 主要经公共互联网传输，Premium 更多使用 Google 骨干网络。更低价格不能保证中国三网访问效果相同，当前没有国内直连测速。档位改变涉及不同公网地址池，修改项目默认档位也不会自动改变已有资源；不能把切换当作无影响的开关。[5][8]

若使用 CDN，应按实际源站到 CDN 的流量和计费路径重算。普通代理不会使所有源站出站自动免费；缓存未命中、私有接口和更新仍会回源。把文件存进 R2 并由 R2 直接交付，与仅给 GCP 加代理是两种部署方式。[2][6]

### 资料存储与下载分开估算

| 明确假设 | 计算结果 |
| --- | ---: |
| 10 人各完整获取当前 85.39 MiB 部署文件一次 | 约 0.834 GiB 有效文件传输 |
| 100 份 PDF，每份 50 MiB，服务器保留一份 | 约 4.883 GiB 存储 |
| 10 人每月各下载其中 20 份 PDF，每份 50 MiB | 约 9.766 GiB 下载 |
| 10 人每天各产生 1 MiB 同步出站，持续 30 天 | 约 0.293 GiB 出站 |

这些是算术情景，不是用户真实用量或后端测试。还应加入 HTTP/TLS、Range 重取、缓存失效、版本更新、备份出口及已有服务流量。同步的 1 MiB/人/日只是显式预算假设。

### $10 赠金

未查看用户账单，尚不清楚赠金来源、能否用于同一结算账号、有效期、剩余金额或适用 SKU。官方 Billing → Credits 可查看状态、剩余额度、一次性/周期性类型、适用服务和起止日期。[4]

## 建议的扩展方式

以下为待实施的架构建议，不是已实现功能或部署授权；最新优先级以自托管方案中的单机和本机空间约束为准。

1. **前端保留现有学习入口，可与 API 集中部署在 GCP，也可继续现有静态托管。** 阅读、练习、复习继续离线可用；拆分题包/资料目录，用户按年份、科目和资料选择下载，避免未来资料全部后台安装。
2. **GCP 承担轻量账号与同步。** 候选为单进程 TypeScript API + 同机 SQLite，复用现有领域/schema 合同。先做邀请制测试、用户数据隔离、增量同步、冲突保留、幂等提交和备份恢复。前端继续通过仓储访问，不把现有本地记录强制迁成只存服务器。[7]
3. **PDF 独立存储。** 初期几 GiB 可评估现有磁盘；持续增加时优先考虑 R2 Standard 等对象存储，让客户端下载资料时不必经过 GCP API 转发。公开与受限材料分别控制访问；文件引用带版本/摘要，保证离线与更新可判断。
4. **电脑按批次开发和处理资料，产物优先远端归档。** 构建、OCR、批量导入和测试事先估计临时峰值；完成后迁出保留证据，不常驻整库和完整备份。北京节点仅在后来需要时作为批处理或独立加密备份候选；不要求它参与网站运行，也不据此认定未备案大陆公开服务已获豁免。
5. **日本节点仅作临时验证候选。** 用户称将到期，不依赖它保存唯一数据或承担长期入口。

R2 Standard 当前免费层为 10 GB-month 存储、100 万次 A 类操作、1000 万次 B 类操作；出站不收流量费，超出免费存储为 $0.015/GB-month。按持续存储 100 GB、请求量仍在免费范围的假设，存储约 $1.35/月；Workers 或其他服务费用另计。尚未开通 R2，也未验证目标用户网络的访问质量。[6]

## 下一阶段需要的验收

- 只读确认 GCP 机型、区域、磁盘类型、当前资源 Network Tier、公网 IPv4 与账单 SKU；确认赠金适用范围，不收集支付卡或凭据。
- 按用户澄清的十几人规模，验收拟设 20 个模拟活跃用户，分别覆盖同时登录、首次同步、增量同步、离线冲突、PDF Range 阅读与下载；注册账号数不代替并发活跃用户验证。
- 记录 API 延迟/错误率、进程 RSS、Linux MemAvailable、活跃 Swap I/O、CPU steal、磁盘余量和实际出站。先测现有其他服务背景负载，再测新增应用。
- 建议验收时给操作系统与已有服务留内存余量、给磁盘留日志和恢复空间；具体数值由实测确定。持续 OOM/换页、CPU 饱和或写入排队后，按瓶颈调整进程/查询/资源。
- 资料访问要实测国内直连；当前浏览器能打开探针不证明其他测试者访问顺畅，尤其不能把带代理访问当直连结果。
- 账号、服务端 schema、收费资源和实际部署需单独实施方案。本轮仅咨询文档与检查点，不修改应用或重复产品门禁。
