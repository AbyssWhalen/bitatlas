### R1 · P1 · 并发首次保存笔记会阻断整库备份

- 位置：`apps/web/src/app/StudyContext.tsx:347–361`；`packages/storage/src/repositories.ts:699–703`；备份唯一性校验在 `packages/storage/src/backup.ts:393–400`。
- 两个标签页都在尚无笔记时读取同一题，分别生成 UUID；仓储按 `id` 写入，没有在事务内落实“一题一条笔记”。并发不是唯一条件：只要两个页面的 notes 快照都还缺该题即可。
- 隔离复现得到两条同题笔记，随后 `exportJson` 报 `Backup data is invalid at data.noteQuestions: Duplicate noteQuestions key.`。原有笔记仍在，不能描述为数据已被删除。
- 修复建议：在现有事务内按 `questionId` 查找并写入；采用显式冲突规则，避免静默覆盖；对已存在重复笔记提供可审查的恢复路径，不能简单删掉一条。优先实现无需变更 schema 的方案。
- 验收：双连接首次保存、旧笔记并发编辑、重复历史导出/恢复、合法 v1/v2/v3 备份均覆盖。
- **信心：高，真实仓储 + fake-indexeddb 已复现。**

### R2 · P2 · 同 hash 快捷路径会把未验证响应写入可信缓存

- 位置：`apps/web/src/app/storage.ts:235–240,340,449–459`。
- 快捷路径比较的是响应中声称的 `manifest.sha256`，没有重新计算实际内容摘要。题干被改但 hash 字段保持原值时，实际校验器拒绝该包，安装流程却跳过校验并把异常 JSON 写入 `408os-content-packs-v2`。
- **现有 IndexedDB 题目不会因此直接改变**。影响是“已验证缓存”不再可信；后续依赖缓存的校验、恢复可能失败。不能把该探针描述为已经证明线上题库被篡改。
- 修复建议：把“响应是否合法”与“数据库是否需要重写”分离；经过完整校验才可缓存，unchanged 仅作为避免重写的优化。
- 验收：同 hash 异内容、合法 unchanged、异常响应不覆盖已有好缓存、离线恢复、verified 防降级。
- **信心：高，真实安装函数 + 校验器 + 模拟 CacheStorage 已复现。**

### R3 · P2 · 扩展年份的离线图片缓存中断后不会自愈

- 位置：`apps/web/src/app/storage.ts:459–461`；`apps/web/vite.config.ts:105–111`。
- 2010–2025 仅在题包有变化时排入延迟 5 秒的资产预热。首次打开后提前关页、网络失败或缓存部分丢失，下次启动发现题包 unchanged，便不再补齐图片。Service Worker 的该图片分支 cache miss 只 fetch，也不会补写。
- 复现：首次安装排 1 次预热；模拟关页丢弃定时回调；再次打开为 **0 次预热、0 次资产请求、0 条图片缓存**。
- 修复建议：每次安装检查缺失资源，以限流队列补齐；显示每年离线准备状态及失败重试。避免启动就无差别重下约 78 MB。
- 验收：首次中断再打开、单张图片丢失、离线/恢复联网、摘要错误、已完整包无额外下载。
- **信心：高，真实扩展安装函数的隔离复现；尚未测真实用户触发频率。**

### R4 · P2 · 模考跨表读取会误报数据损坏

- 位置：`packages/storage/src/mock-repository.ts:283–289`。
- `getExam` 分两次读取 exam 与 session，没有共同只读事务。另一连接恰好在中间完成一次合法保存时，读取组合可能是旧 exam + 新 session，从而抛出 `Mock exam timestamps do not match its session.`。
- 探针强制调度边界后复现错误；实际两条持久化记录的时间戳完全相同。该路径也供实时订阅使用，可能造成加载/同步错误。
- 修复建议：把两表读取及一致性检查放入同一只读事务。检查其他需要联合一致性的读路径。
- 验收：读写交错、初次加载、实时订阅、确实损坏的数据仍须拒绝。
- **信心：高，真实双连接写入已复现；浏览器发生频率未知。**
- 产品边界：默认草稿题包的正式模考入口目前关闭，此问题主要影响已安装 verified 题包后的模考流程。

### R5 · P2 · 至少 9 道题的提示直接给出正确选项

- 位置：`tools/content-importer/src/build-year.mjs:430–434,481–482`；提交前提示入口 `apps/web/src/pages/PracticePage.tsx:576–581`。
- 导入器将解析首句当成知识点名称，又将该名称当第一提示，直接泄露答案。实际题包逐条核对：2014 Q08/21/25/30/33、2015 Q38、2017 Q26、2019 Q03、2021 Q11；9 条提示中的选项均与正确答案一致。
- 例如 2014 Q30：“只有 FIFO 算法才会导致 Belady 异常，选 A”。这类文字也成为知识点标题。
- 修复建议：分离概念名、启发提示和答案解析。缺少可靠提示可留空，不从解析机械截句。修复生成逻辑与受影响真实题包，保持来源和审核状态；不要仅增加“选 A”正则遮罩，泄题可能没有该固定格式。
- 验收：真实 9 题回归、抽样语义复核、重新生成确定性、题包校验；依现有版本合同区分题面变化与纯提示变化。
- **信心：高，真实题包与生成代码双重确认。**

### R6 · P2 · 创建练习及导出备份失败时缺少可见反馈

- 位置：`QuestionsPage.tsx:52–55`、`WrongPage.tsx:11–14`、`DashboardPage.tsx:50–62`、`SettingsPage.tsx:18–29`。
- 这些异步入口没有 catch；创建入口也没有 pending 防重入。数据库读写拒绝、配额错误或 R1 的备份校验错误不会转成页面可操作的错误状态。
- 修复建议：统一 pending/error/retry 模式；尤其确保导出失败不会让用户以为已备份。知识图/模考已有相似模式可复用。
- 验收：注入存储错误、显示失败、重试成功；快速重复点击只创建一个会话。
- **信心：高，静态确认；本轮未针对这些入口执行浏览器故障注入。**

### R7 · P3 · 统计页跨北京时间午夜不会自动刷新日期

- 位置：`apps/web/src/pages/StatsPage.tsx:25–29`。
- 热力图的 memo 只依赖 `currentAttempts`。没有新作答时，停留到午夜或电脑休眠后恢复会继续显示旧日期。总览已有 `useBeijingDate`，统计页没有复用。
- 修复建议：接入同一日期 hook，覆盖午夜、休眠恢复及卸载清理。
- **信心：高，静态确认；本轮未另跑浏览器快进时钟复现。**

## 下一步建议

### 第一阶段：可靠性和明确内容错误

先修 R1–R4 与导出失败反馈，再修 9 条泄题提示；R7 可随同小改处理。每项先建立反例，再做最小修复，最终跑全仓门禁。依赖更新单独一批，避免把包升级与数据逻辑同时混改。

完成标准：并发笔记仍可完整备份；模考合法并发不误报损坏；异常题包不污染缓存；离线图片中断后可补齐；提示帮助思考而不直接给答案。

### 第二阶段：真正的学习闭环

1. **从“题目节点图”变成跨年概念组织。** 目前每年是 4 个学科根 + 47 个题目节点，知识页以 2009 为主。先做一小批高频概念，把多年份真题、错因、相关实验和下一次复习连起来。
2. **错题入口补年份与单题重练。** 当前跨年列表和每日计划的 Q 编号容易混淆。增加年份/科目筛选、明确单题入口、完成练习后的本次复盘，再回到计划。
3. **内容分批提升质量。** 80 题缺文字解析、791 条模板第二提示仍是主要质量债。按高频概念小批补齐来源、解释和提示；自动检查不能替代人工审核，也不能自动将 799 题设为 verified。
4. **决定正式模考的产品边界。** 默认 2009 题包尚未通过人工审核，因此入口关闭是现有合同，不是这次发现的故障。若需要草稿模拟练习，应另行明确命名、标识和评分边界，不能暗中取消门禁。
5. **阅读体验少一些装饰负担。** 三张目检截图布局正常；持续扫描线、光晕、低对比小字对长时间刷题未必有帮助。建议增加安静阅读样式，先用真实用户任务验证；这是设计建议，不是已证明的可访问性缺陷。

### 第三阶段：维护性与资源治理

- 拆分 `StudyContext` 中的内容安装、练习、笔记、复核和模考服务；减少每次小写入后的全表重载。先测量再拆，不做无边界重构。
- 题包生命周期增加 stale assets/cache 的回收与同年份 manifest 唯一性，维护可恢复的离线准备状态。
- 将 `HANDOFF.md` 维护成短的当前状态，历史分档；目前 HANDOFF 与 notes 各约 400 KB，历史“未提交/已部署”快照并存会增加接手成本。归档必须保留原文与索引。
- 测试证据按“本轮成功摘要 / 待解决失败原件 / 已关闭问题归档”设保留规则。测试截图用 run 独立路径，避免每次复跑覆盖上一轮截图。

账号、邮件验证码、云同步暂排在这些工作之后：会引入身份、同步冲突和迁移成本，但不能解决当前提示质量、并发写入和离线恢复问题。上述为下一阶段实施计划，本轮没有进行大改。

## 未验证候选
