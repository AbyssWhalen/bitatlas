## PWA：更正、设计边界和有效证据

**新匿名访客在登录前不注册 service worker，属于本次确认保留的设计边界。** `PwaUpdateNotice` 位于 `AccountGate` 的登录后子树内；旧真实部署构建与新候选均如此。Git 在 `eb4ff56` 收入这一结构，但旧线上构建早于该提交，不能用提交日期断言生产行为何时开始。[实施合同](implementation.md)要求“未退出账号离线资格 7 天”，不承诺全新匿名访客离线登录。组长本轮明确裁定保留该设计，不列为缺陷，不改产品代码。

首次匿名离线 reload 的原始错误为 `page.reload: net::ERR_INTERNET_DISCONNECTED`。诊断发现匿名环境实际 `registrations=0`、`controller=false`、Cache Storage 为空。执行脚本用 `waitForFunction(async …)` 等待注册，Promise 被视为真值，产生错误的“已受控”标记。17:43 的失败回执 `public-resume-fresh.json`、诊断 `offline-diagnose.json` 原样保留；后者同步等待 controller 激活确实超时。14:23 停点的 `public-old-ready.json` 和恢复轮 `public-resume-old-ready.json` 均受同一错误影响，**不能证明旧匿名 PWA 已安装**。恢复轮 transition 停在等待注册，已终止；没有取得公网旧→新 PWA 成功结论。

为判断是否影响成员，使用逐文件摘要匹配的真实旧/新静态构建、内存 SQLite 和合成成员完成 [本机对比](../../output/release-execution-2026-11-25/pwa-member-comparison-1795600068127/receipt.json)，没有访问生产账号：

- 旧、新匿名冷访均无注册与缓存，断网重载均为相同错误。
- 登录后旧版 87、新版 95 项预缓存完整；每次等待同步的 `controller.state === 'activated'`。
- 旧→新→旧两次均用真正等待 `evaluate` 返回值的轮询，确认 waiting 及可见更新提示，旧页保持原入口；关页重开加载目标 JS。
