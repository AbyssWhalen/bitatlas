# Opus 复查与 UI 样张评审

对应维护者提供的 2026-11-22 复查、七张说明截图及 `<downloads>/BitAtlas_.html`。本轮获准评审，没有获准恢复产品实施。以下建议不是提交、部署、schema 变更或新增功能授权；没有修改 Opus 文件。

结论：维护方向的大部分批评成立，但 P0 定级偏重、A1/A5 的现状判断有误，A2/A7 需要修改设计。UI 的寄存器、键帽、任务票值得保留；建议降低粗边框和高亮面积，把阅读、移动触控和真实学习数据放在视觉隐喻之前。事实核验信心高，视觉偏好为主观判断；公网根因和最新依赖风险仍未在本轮定案。

## 只读UI接口与ID检查

- 概念进度接口值得抽取，但先确定口径：`attempted`指题目数还是题次；`correctRate`是纯客观正确率还是现有知识页的综合performance；手工掌握、卡片自评、无提示首答不能混成一个百分比。现有知识页聚合还有近期加权与主观得分，不能简单改字段名叫“正确率”。按当前题面/卡片版本过滤，未检测必须与0%区分。
- 学习天数按北京时间派生合理。活跃应来自有效作答/卡片事件，而非仅登录；今日还没练但昨天练过时如何显示连续天数、周一为周起点等应写明，不增加惩罚。
- 会话/同步只读接口必要。离线资格不是“离线下载完成”，空outbox也不是“最近成功同步”。代码有成功同步事件，但没有现成可跨刷新保留的lastSuccessfulSync字段；可先返回null/未知或本会话时间，不能编造。是否持久化另作小范围设计。
- 卡片当前**没有title字段**。可由`conceptIds`查真实概念名，或由front的文本块派生短标签；不用从`card-ds-01`解析科目。此次对domain/storage/server/app相关模式搜索未发现由题目/卡片ID反推年份/科目的运行时逻辑；这是有界静态检查，不是全仓形式证明。`DailyTasks`的replace是展示层缺陷，与ID算年份导致数据库溢出不是同一种后果。
- 字体优先打包为本地woff2并验证server/local两个构建。现有Workbox glob已包含woff2，未必需要新增glob；server模式publicDir关闭时还需确保实际复制或导入字体。得意黑官方LICENSE确为OFL1.1，保留字体名条款需在子集化时核对；300KB只是预算，尚无字体产物可验。当前HTML实际从Google Fonts加载替身和JetBrains Mono，并未携带得意黑。

## UI判断与实测

主观建议：选择“方向对，但更克制”。顶部导航、键帽、黑白底色与少量红/绿强调有辨识度，寄存器可作为概念地图缩略入口；任务票可直观显示当前步骤。练习题和公式区减少硬阴影、粗边框和倾斜，亮绿适合强调状态，不宜占满长期阅读区。大标题可缩小一级，为“继续学习”和题目内容让出空间。

建议保留桌面顶部导航，手机继续遵守现有“今日/题库/复习/知识/更多”底栏合同；实验可由更多、概念详情和任务关联直达。寄存器手机可折叠为科目概览，不强迫用户点击102个小格。十六进制串可作为可隐藏装饰，不承担实际进度说明。

真实Chrome读取原HTML，1440桌面、390手机模拟、390普通窄窗均执行，昼夜切换与挖空键盘揭示可用；0 pageerror不代表产品功能已接通。主要发现：

1. **缺viewport meta。** 手机模拟布局宽980px、scale约0.398，显示为缩小的桌面。普通390窄窗虽无整页横溢，但任务票内部348px宽承载681px内容。后者需清楚的滑动提示或移动纵向布局。
2. **15×20px比特按钮过密，间隔3px。** 不能作为手机主要入口；键盘focus不更新概念提示，点击后提示文本仍停留旧状态。共有123个可聚焦元素，102格逐个Tab也缺少有效分组导航。
3. **色彩与字级还需调整。** 正文题干18px，但整体body16px，状态/图例10–13px。白字与#FF5A36实际对比约3.10:1，样张13px错因chip和18px粗体主按钮不能都按大字例外处理；建议更深红背景或深色文字。夜间等待动画结束后正常，首张过渡中截图不作为主题缺陷证据。
4. **演示数据不能迁成业务逻辑。** 102格状态用种子随机数，概念名字循环填充；点击格子直接轮换掌握状态。正式版应点开概念详情/练习，状态由学习记录派生。hex仅截最后12位，最多显示低48bit；实测第一格变成掌握，读数仍不变。顶部“8个比特”也不能拿5题+3卡直接充数：任务与概念是多对多。
5. **多处只画了入口。** 导航、继续、A–D/数字评分/方向键没有完整事件实现；A键不改变选项，点击题库仍留在今日。草稿、打印、登录动画只出现在说明表。作为视觉样张可以，不能据此宣称完整新前端已完成。
6. **样例内容需纠正。** HTML给Cache取模算例挂“2014 Q21”，当前该真题实际是I/O接口题。129 mod 16=1，样张选中的B也为1，却紧接“答错了”。卡片“只有FIFO会出现Belady异常”缺比较范围，应明确是在所比较的算法中或改为“FIFO可能出现”。自编样例应标“示例题”，不借真题身份。
7. **挖空不宜仅靠同色字遮盖。** 当前答案文本已在DOM中，仅设置黑字黑底；Tab可达但没有button语义、展开状态，辅助技术可能直接读出答案。正式实现应区分未揭示/已揭示内容，并保留先回忆再评分的合同。键盘字母快捷键也须避开输入框、笔记、输入法组合态和快捷键冲突。

W3C目标尺寸解释页给出24×24 CSS px及间距等例外；当前相邻比特中心距18px，既小又近。对比度解释页给出普通文字4.5:1、大字3:1；这为上述整改提供依据，不是一次完整WCAG审计。官方原文下载与来源记录在[official-references](../../output/playwright/opus-prototype-review-2026-11-22/official-references/results.json)。

截图中的其余意见：

- `/review`与`/review/2009`语义不清成立，但React路由不是因此发生运行时匹配冲突。可以把内容复核整理到管理入口，旧地址保留兼容跳转；成员界面也应隐藏/禁止相关操作，继续保留服务端权限。
- 文案应更直接；“昨天那题今天会出现”只有真实清单包含时才能说。规则解释可以收进帮助，不删掉首次作答/评分边界。
- 尚未开放的正式模考可移出主导航或放到更多注明条件；保留既有模考历史可访问性，不能把旧记录一起藏掉。
- 实验从概念直达值得优先做；先复用已有lab链接，不必为102个概念编造实验或一次重写全部实验布局。
- 字号入口可收进阅读工具菜单/设置，保持正文页容易找到和18px默认。不要为精简界面把阅读辅助完全藏深。
